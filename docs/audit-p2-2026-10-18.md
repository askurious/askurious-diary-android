# P2-Korrekturen des Datenspeicherungs-Audits

Die Integration auf main erhält die verschlüsselte SQLite-Warteschlange, die Serverauswahl und die aktuelle Navigation.

- T3: Eine vor der Online-Anfrage gespeicherte UUID wird auch beim Offline-Nachsenden verwendet. Warteschlangen-Wiederholungen bewahren die erste Antwort und lehnen eine andere Befragung bzw. einen anderen Abfragezeitpunkt unter derselben UUID ab.
- T4: Ausstieg ist lokal sofort wirksam. Erst nach bestätigter Übertragung aller wartenden Antworten wird der Server benachrichtigt. Fehler bleiben als ausstehend sichtbar und werden erneut versucht. Synchronisationsantworten werden atomar mit lokalen Änderungen zusammengeführt.
- T5: Die vom Server gelieferte Zeitzonenhistorie bleibt beim Speichern erhalten und bestimmt Termine und Tagesgrenzen. Ältere Server ohne diese Angaben verwenden weiterhin die Gerätezeitzone.
- T6: Das lokale Tageslimit zählt selbst gestartete Antworten nach ihrem Starttag, nicht nach dem Absendezeitpunkt. Antworten auf zeitgesteuerte Abfragen zählen nicht dazu.

## Tests und Grenzen

Die vollständige lokale JVM-Testsuite einschließlich gezielter Regressionstests wird ausgeführt; Ergebnisse stehen in der PR-Beschreibung. Die Tests prüfen Wiederholungen, Identitätskonflikte, Mitternacht, Zeitzonenwechsel, lokale Änderungen während einer Synchronisation sowie die Reihenfolge Upload/Ausstieg.

Dauerhaft abgelehnte Antworten können die serverseitige Austrittsmeldung weiter zurückhalten. Entfernen oder Löschen bleibt eine ausdrückliche Handlung der teilnehmenden Person. Bestehende Duplikate werden nicht repariert. Kein Test auf realen Geräten bei Stromverlust oder während echter Netzwechsel, kein App-Release.

Rechtstexte geprüft: Die Hinweise zum Ausstieg wurden in allen zwölf Sprachen an die Übertragungsreihenfolge angepasst. Speicherung, Empfänger und Löschmöglichkeiten ändern sich nicht; keine zusätzliche Anpassung der Datenschutzerklärung nötig.
